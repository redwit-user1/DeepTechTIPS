# 구노 연구노트 작성 지침 (v2)

보고서가 아니라 연구자가 그날 적은 노트처럼 보여야 함. 양식이 반듯할수록 AI가 쓴 티가 남.

## 1. 원칙 세 가지

1. 그림이 먼저, 글은 그림 설명. 수치가 나오는 결과는 그래프로, 절차와 구조는 흐름 그림으로 그림
2. 표와 선은 데이터를 담을 때만 사용. 꾸미거나 정리하려는 용도로는 쓰지 않음
3. 말투는 개조식 + 김하림 말투. 결론부터, 한 줄에 한 생각, 쉬운 말

내용 기준은 그대로: 레포의 `docs/notebook/*.md`, 커밋 이력, 실측 로그. 원본에 없는 수치와 해석은 쓰지 않음.

## 2. 양식

쓰지 않는 것

- 맨 위 개요 표 (연구 일자, 단계, 주제를 표로 정리한 것)
- 구분선, 인용 상자, 글상자
- `2.1`, `2.2` 같은 소절 번호와 3단계 이상 목차
- "연구 목적 / 수행 내용 / 결과 / 정정 사항 / 결론 및 차기 과제"를 매번 똑같이 채우는 틀
- 굵은 글씨 남발. 한 노트에 두세 곳, 꼭 봐야 하는 숫자에만
- 2단계 넘는 들여쓰기 목록

쓰는 것

- 첫 줄: 날짜와 커밋만 한 줄로. 예: `2026-08-01, 커밋 0b9461a / afa137c / 2f2aa39 / 0fe6c36`
- 그다음 바로 그날의 핵심 그림 1장과 결론 두세 줄
- 제목(소제목)은 그날 한 일을 그대로 적은 짧은 말. 3~5개면 충분. 예: `평가셋을 실데이터로 바꿈`, `고친 것 3건`, `다음에 할 것`
- 소급 작성한 노트는 첫 줄 바로 아래에 한 줄로 밝힘. 예: `2026-08-31에 소급해서 정리한 노트임. 근거는 사업계획서와 docs 문서`

표를 써도 되는 경우

- 측정값이 3행 이상이고 그래프로 그리면 값이 안 읽힐 때
- 그래프에 쓴 원 수치를 남겨야 할 때(그림 바로 아래에 작은 표로)
- 그 외에는 문장이나 그림으로 풂. 항목과 설명을 2열로 나열하는 표는 금지

## 3. 그림 규칙

- 노트 1건에 그림 최소 1장. 결과 수치가 있는 절에는 그래프 1장씩
- 종류 고르기
  - 크기 비교: 가로 막대 (`bar`)
  - 고치기 전과 후: 전후 점 그림 (`change`)
  - 절차, 파이프라인, 판정 순서: 흐름 그림 (`flow`)
  - 실제 화면, 학습 곡선, 로그 캡처가 있으면 그게 제일 좋음. 그대로 붙임
- 그림 제목은 결론을 적음. "F1 비교" 말고 "같은 게이트웨이인데 실데이터에서는 24%"
- 강조는 한 가지 색(파랑)만, 나머지는 회색. 값은 막대나 점 옆에 직접 적음
- 격자선, 테두리, 범례 상자, 3D, 이중 축 없음
- 단위가 다른 값은 한 그림에 섞지 않음
- 그림 아래 캡션 한 줄: `그림 1. 무엇을 어떤 범위(전수/표본 N건)로 잰 것인지`
- 그림에 쓴 수치는 전부 원본에 있는 값이어야 함

만드는 법

```bash
node .claude/skills/goono-research-note/make_figure.cjs <스펙.json> <출력.svg> --png
```

스펙 예시는 `make_figure.cjs` 맨 위 주석 참고. PNG는 2배 해상도로 나옴.

- 원본 표기를 그대로 찍어야 하면 값을 문자열로 넣음. 예: `"value": "24.0"`, `"value": "+2.0"`
- 전후 점 그림의 회색과 파랑이 수정 전후가 아니면 `"legend": ["sft_v2", "dpo_v2"]` 처럼 범례 문구를 지정
- 흐름 그림은 한 줄에 5단계 정도까지. 넘으면 두 줄로 꺾이므로 되돌아가는 화살표는 따로 그림

## 4. 말투

개조식이되 계획서처럼 딱딱한 명사 나열이 아니라, 본인이 팀에 공유할 때 쓰는 말투를 그대로 줄인 것.

말투 특징 (슬랙 공유 글, 업무 목록, 작업 지시에서 뽑음)

- 결론부터 적음. "결론부터 말하면 합성 점수는 못 씀"
- 한 줄에 한 생각. 길어지면 줄을 바꿈
- 쉬운 말. "수립, 확보, 도출, 제고, 고도화" 같은 계획서 단어 대신 "만듦, 구함, 뽑음, 올림, 고침"
- 판단과 사실을 구분. 본 것은 단정("24.0% 나옴"), 생각은 "~로 보임", "~같음", "~로 판단"
- 솔직하게 적음. 안 된 건 안 됐다고, 틀린 건 틀렸다고. "생각보다 안 나옴", "이건 내가 잘못 봤음"
- 이어 주는 말은 "일단", "다만", "그래서", "여기에", "또" 정도만
- 숫자는 어림일 때 "약", "정도", "최소"를 붙이고, 잰 값은 그대로
- 이유는 짧게 붙임. "~라서", "~때문에"
- 할 일은 "~ 체크", "~ 정리", "~ 확인", 기한은 괄호로 "(~11.20)"

끝맺음

- 사용: ~함, ~했음, ~됨, ~임, ~없음, ~같음, ~로 보임, ~필요, ~예정, ~못 함, ~안 됨, 명사로 끝내기
- 금지: ~다, ~했다, ~합니다, ~해요 같은 서술형. 노트 본문에는 존댓말도 쓰지 않음

바꿔 쓰기 예

| 계획서식 (쓰지 않음) | 노트 말투 |
|---|---|
| 합성 평가셋의 낙관 편향 제거 및 방어 가능한 성능 기준선 확립 | 합성 평가셋 점수는 너무 잘 나와서 못 믿음. 실데이터로 다시 잼 |
| 외부 실데이터 평가셋으로 교체하여 학습과 평가 분리 강제 | 평가셋을 SciFact로 바꿈. train으로 학습, dev로만 측정 |
| 정정 전 → 정정 후: 98.2%를 성능 근거로 사용 → 회귀 테스트 용도로만 유지 | 98.2%는 성능 근거에서 뺌. 회귀 확인용으로만 남김 |
| 트랜스포머 NLI 도입이 KPI 달성의 필수 조건임을 확정 | 규칙만으로는 안 됨. NLI 모델을 넣어야 KPI가 나올 것으로 보임 |

그 밖에 피할 것: "즉", "결론적으로", "핵심은", "~라는 점에서", "~를 통해", 같은 구조의 문장 세 개 연달아 쓰기, 항목마다 `이름: 설명` 꼴로 맞추기.

## 5. 금지 기호

| 금지 | 대체 |
|---|---|
| 가운뎃점 `·` | 쉼표, 빗금(/), "및", "과" |
| 줄표 `—`, `–`, `―` | 문장을 나누거나 괄호 |
| 문장을 잇는 하이픈 ` - ` | 문장을 나눔 |
| 이모지, `✓`, `★`, `▸`, `※` 류 | 쓰지 않음 |
| 수식의 곱셈 `·` | `×` |

허용되는 하이픈: 날짜, 모델명과 식별자(`WF-A`, `Qwen3.8-27B`), 파일 경로. 범위는 물결표(`1~3회`). 전후 변화의 화살표(`42.9% → 100%`)는 써도 되지만 한 노트에 몇 번만.

## 6. 기록 원칙

- 원본의 측정값, 건수, 커밋, 정정 이력은 빠뜨리지 않음. 글은 줄여도 숫자는 남김
- 판단이 뒤집힌 건 지우지 않고 "처음엔 이렇게 봤는데 틀렸음" 식으로 남김
- 수치에는 전수인지 표본인지, 표본이면 몇 건인지 적음
- 고객 실데이터의 원문, 실명, 파일명은 넣지 않고 집계값만

## 7. 예시 (2026-08-01 앞부분)

```markdown
2026-08-01, 커밋 0b9461a / afa137c / 2f2aa39 / 0fe6c36

![같은 게이트웨이인데 실데이터에서는 24%](fig/2026-08-01-1.png)

그림 1. 같은 게이트웨이를 합성 평가셋과 SciFact dev로 각각 잰 F1

결론부터 적으면 합성 평가셋 점수(98.2%)는 성능 근거로 못 씀.
같은 게이트웨이가 실데이터에서는 24.0% 나옴.
이후 성능 얘기는 전부 외부 실데이터 기준으로 적기로 함.

## 평가셋을 실데이터로 바꿈

- 합성 평가셋은 템플릿으로 만든 거라 너무 쉬움. 회귀 확인용으로만 남김
- SciFact로 교체. train으로 학습하고 dev로만 측정하게 코드에서 막아 둠
```

## 8. 구노 업로드 절차

대상: `https://service.goono.so` 의 "딥테크 TIPS" 과제. 브라우저 조작은 `ego-browser` 스킬 사용.

1. 시간순(오래된 연구 일자부터)으로 한 건씩 등록
2. 에디터 등록: 에디터 → 에디터 작성하기 → 제목 입력 → 빈 문서 → 생성하기 → 본문 붙여넣기 → 저장 → 작성 완료하기 → 폴더 확인 → 작성일자 선택 → 파일 추가
   - 그림은 본문 HTML에 `<img src="data:image/png;base64,...">`로 넣어 같이 붙여넣으면 저장과 변환 뒤에도 남음 (2026-11-14 확인)
   - 그림 3장 이하의 짧은 노트에 적합
3. 파일 등록: 그림을 넣은 PDF로 변환 → 연구노트 홈 → 파일 추가 → 파일 선택 → 작성일자 선택 → 파일 추가
   - 그림이 많거나 긴 노트는 PDF로 등록
4. 작성일자는 실제 연구 일자로 지정. 시점인증 일자는 등록 시각으로 고정되고 수정 불가
5. 등록 후 목록에서 제목과 작성일자 확인, 한 건은 열어서 그림이 보이는지 확인
6. 이미 시점인증된 노트를 지우고 다시 올리는 건 사용자 확인을 받고 진행

## 9. 검사

```bash
python .claude/skills/goono-research-note/lint_note.py <작성본.md> [원본.md]
```

- 실패: 금지 기호, 서술형 종결, 그림 없음, 개요 표, 구분선, 소절 번호(2.1 등)
- 경고: 표 3개 이상, 굵은 글씨 4곳 이상, 계획서 단어, 원본에 없는 수치
