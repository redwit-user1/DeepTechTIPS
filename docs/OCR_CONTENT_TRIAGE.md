# GOONO OCR 코퍼스 — 내용 중심 판정 결과

> 이전 문서(`OCR_REAL_FINDINGS.md`)의 판정을 **정정**한 기록.
> 원문·파일명은 포함하지 않는다.

## 왜 다시 했나 — 잣대가 틀렸다

앞선 분석은 국가연구개발 연구노트 **지침 양식**(과제명·연구자 서명·점검자·구획
헤더)을 기준으로 삼아 "구조성 지수 0.07 → 연구노트가 아니다" 라고 판정했다.

**이 잣대가 틀렸다.** 연구노트의 본질은 담긴 **연구 내용**이고, 서명·양식 같은
형식 요소는 부차적이며 애초에 이 코퍼스에 담기지 않는다. 업로드된
PDF·PPTX·XLSX 가 곧 연구 기록 그 자체다.

### 프로젝트 방향에 미치는 영향

| | 이전 판단 | 정정 후 |
|---|---|---|
| `integrity/` 양식 검사 | 핵심 모듈 | **가치 낮음** — 검사 대상이 이 데이터에 없다 |
| 내용 근거 검증(VCR) | 부차적 | **핵심** — 연구 내용에 대한 주장이 실제 데이터에 근거하는가 |
| 조각으로 버린 구간 | 폐기 | **대부분 실제 연구 내용이었다**(아래) |

## 분류기 결함 두 건 — 실데이터가 잡아냈다

### ① 흩어진 신호를 놓쳤다

1차 분류는 모든 조건이 **"한 종류 신호가 3개 이상"** 을 요구했다.
그래서 `수치 2 + 실험용어 2 + 분석어 2` 처럼 여러 종류에 흩어지면 어느 조건도
넘지 못하고 전부 `fragment` 로 밀려났다.

`scripts/inspect_fragment_bucket.py` 로 조각 버킷 17,917건을 검사한 결과:

| 신호 개수 | 비율 | 판정 |
|---|---|---|
| 0개 | 47.1% | 정말 내용 없음 |
| 1~2개 | 31.2% | 임계값 미달 |
| **3개 이상** | **21.7%** | **명백한 분류 오류** |

- 숫자 10개 이상 포함: **64.4%** (표·측정값)
- 길이 300자 이상: 67.2% (중앙값 533자 — 짧아서 밀린 게 아니다)

→ 신호 총합이 임계값을 넘으면 **가장 강한 신호의 범주**로 배정하도록 수정.

### ② `code_meta` 는 도달 불가능한 분기였다

GitHub 하위 분류에서 설정·메타가 **0건**으로 나왔는데, 데이터가 없어서가 아니라
진입 조건(`commit≥2 or code≥4 or (repo≥3 and markdown≥3)`)을 통과하면
하위 세 분기 중 하나가 반드시 참이 되어 `code_meta` 에 도달할 수 없었다.
`repo≥4` 단독 조건을 추가해 `package.json`·`Dockerfile` 류를 잡도록 수정.
→ 0건 → **7.1%(약 46만행)**

## 연구 데이터와 GitHub 콘텐츠는 검증 방식이 다르다

별도 정리가 필요한 이유다.

| | 실험 기록 | GitHub 콘텐츠 |
|---|---|---|
| 무결성 관건 | 수치·조건·근거 일치 | **재현성**(의존성·버전·시드) |
| 귀속(Attributable) | 연구자 | **커밋 작성자·GPG 서명** |
| 동시성(Contemporaneous) | 실험일 | **커밋 타임스탬프** |
| 원본(Original) | 정정 이력 | **git 히스토리 자체** |
| 추가 리스크 | — | 코드 라이선스 충돌, 비밀키 유출 |

**커밋·diff 약 16만 행**은 GOONO 의 블록체인 시점인증과 자연스럽게 맞물린다.
커밋 이력은 그 자체로 `Contemporaneous`·`Attributable` 의 **기계 검증 가능한
증거**이며, 서명·양식 점검보다 훨씬 실질적인 근거다.
