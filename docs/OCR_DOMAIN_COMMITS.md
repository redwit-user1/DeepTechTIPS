# 분야 분류 · 커밋의 연구 관련성

> `OCR_CONTENT_TRIAGE.md` 의 내용 버킷 위에 **두 축**을 더 얹은 결과.
> 원문·파일명은 담지 않는다. 시각화 리포트: `GOONO 코퍼스 지형도` 아티팩트.

## 1. 연구 분야 — 표본 60,000행 중 연구 버킷 27,927행

국가과학기술표준분류 대분류 기준. 신호 2개 미만이면 미분류.

| 분야 | 비율 | 전체 추정 |
|---|---|---|
| 미분류 | 37.0% | 1,122,857 |
| **생명·보건의료** | **22.7%** | 687,971 |
| 정보·통신 | 9.9% | 301,334 |
| 재료·소재 | 7.2% | 218,203 |
| 화학·화공 | 6.1% | 184,842 |
| 기계·제조 | 4.4% | 133,008 |
| 에너지·환경 | 4.1% | 123,989 |
| 전기·전자·반도체 | 3.5% | 107,037 |
| 농림수산·식품 | 2.6% | 79,435 |
| 건설·교통 | 1.5% | 45,422 |
| 기초·자연과학 | 1.0% | 30,644 |

분류된 행만 놓고 보면 생명·보건의료가 **36%**, 상위 4개 분야가 **73%**.

### 유형별 주도 분야

| 내용 유형 | 1위 | 2위 | 미분류 |
|---|---|---|---|
| 실험 기록 | 생명·보건의료 25% | 재료·소재 7% | 39% |
| 분석·해석 | 정보·통신 18% | 생명·보건의료 16% | 32% |
| 문헌·인용 | 생명·보건의료 30% | 정보·통신 19% | **25%** |
| 계획·제안 | 정보·통신 14% | 기계·제조 10% | 39% |

문헌·인용의 미분류가 가장 낮다 — 인용문은 분야 용어 밀도가 높다.
한국어 VCR 평가셋 1순위 근거가 하나 늘었다.

### 학습 전략에 미치는 영향

단일 범용 LoRA 대신 **생명·보건의료 전용 + 범용** 2단 구성.
상위 4개가 73%이므로 나머지 6개는 범용에 묶어도 손실이 작다.

## 2. GitHub 코드의 연구 관련성 — 코드 버킷 8,750행

분석·실험·모델 신호 vs 빌드·배포·의존성 신호로 갈랐다.

| | 비율 | 전체 추정 |
|---|---|---|
| 판별 불가 | 46.6% | 443,144 |
| **연구 코드** | **31.9%** | **302,964** |
| 인프라 코드 | 21.5% | 204,728 |

**GitHub 콘텐츠를 "코드니까 연구가 아니다"로 묶으면 30만 행을 버린다.**

연구 코드의 분야는 연구 *문서*와 확연히 다르다 — 정보·통신 47.8%(문서에서는 9.9%),
재료·소재 9.1%, 생명·보건의료 8.8%. 분석 스크립트는 어느 분야든 파이썬·통계 어휘를
쓰기 때문이며, **코드에는 분야 LoRA 가 아니라 별도 처리가 맞다**는 신호다.

## 3. 커밋 메시지로 본 연구 활동 — 커밋성 2,460행

커밋 메시지는 연구자가 자기 작업을 스스로 요약한 한 줄이다.
"오늘 무엇을 했는가"라는 점에서 연구노트와 기능적으로 같다.

| 활동 | 비율 | 평균 길이 |
|---|---|---|
| 유지보수 | 40.7% | 1,273자 |
| 미분류 | 16.6% | 1,142자 |
| ★ 데이터·실험 | 14.1% | 1,613자 |
| 인프라·환경 | 9.4% | 1,802자 |
| ★ 평가·결과 | 5.1% | 1,597자 |
| 문서·보고 | 4.8% | 1,631자 |
| ★ 모델·알고리즘 | 3.9% | **1,964자** |
| ★ 전처리·정제 | 3.4% | 1,708자 |
| ★ 분석·시각화 | 2.1% | 1,680자 |

**★ 연구 활동 28.6%** (704/2,460, 전체 약 76,501행).
사용자 가설대로 **커밋 내용으로 연구 활동을 가를 수 있다.**

연구 활동 커밋 평균 1,713자 vs 유지보수 1,273자 — **+42%**.
연구를 기록한 커밋이 일관되게 더 길다.

### ALCOA+ 기계 검증 요소 (커밋성 행 대비)

| 요소 | 비율 | ALCOA+ 대응 |
|---|---|---|
| 커밋 해시 | 76.5% | Original |
| diff 본문 | 16.1% | 변경 근거 |
| Date 헤더 | 13.3% | Contemporaneous |
| Author 헤더 | 4.4% | Attributable |

**Author 4.4% 는 코퍼스의 한계이지 GitHub 연동의 한계가 아니다.**
OCR 은 화면에 보이던 것만 담았다. 귀속·시점은 git 원본에 온전히 있으므로
연동 파이프라인에서 직접 읽으면 100% 기계 검증 가능하다.

### Conventional Commit 타입 — 총 7,199건

feat 2,831 / fix 2,596 / chore 662 / refactor 587 / style 173 / test 150 /
docs 107 / build 47 / ci 35 / revert 11 / perf 10.

feat+fix 가 75% — 전형적인 제품 저장소 분포다. 연구 코드가 제품 저장소와 섞여 있다.

## 4. 실데이터가 잡아낸 정규식 결함 두 건

합성 데이터에서는 드러나지 않았다.

| 결함 | 증상 | 원인 | 효과 |
|---|---|---|---|
| 빈 정규식 대안 | "인프라 코드 100%" | 패턴 끝의 `|` 가 빈 대안이 되어 모든 위치에 매치 | 전면 재실행 |
| 해시 오탐 | 커밋 해시 80.4% | `[0-9a-f]{7,40}` 가 순수 숫자열도 해시로 인정 | 80.4 → 76.5% |

전자는 `assert not INFRA_CODE.search("")` 로 회귀를 막았다.

## 5. 한계

- **정확도가 아니다.** 정답셋이 없으므로 이 수치는 "분류기가 어떻게 나눴는지"일 뿐이다.
- **유지보수 40.7% 는 과대**다. 패턴에 `fix`·`merge branch` 가 들어 있어 다른 활동의
  커밋도 끌어온다. 연구 활동 28.6% 는 **하한선**으로 읽어야 한다.
- 표본 0.92%(앞부분 연속 6만 행)라 업로드 시점 편향이 있을 수 있다.
