# 국내 연구데이터 특화 데이터셋

기존 평가는 **영어·바이오(SciFact)** 한정이었다. 과제 KPI 는 한국어 R&D 문서가 대상이므로
한국어·국내 연구 맥락의 데이터가 필요하다. 그 격차를 메우기 위한 작업.

## 확보 현황

| 출처 | 상태 | 내용 |
|---|---|---|
| **ClinicalTrials.gov (국내 기관)** | **확보** (MCP) | 국내 연구기관 연구과제 **22건 실데이터** |
| bioRxiv/medRxiv | 확보 (MCP) | 국내 기관 프리프린트 |
| arXiv | 차단 | egress 정책 — `ArxivAdapter` 준비 완료(파서는 오프라인 테스트됨) |
| ScienceON / NTIS | 차단 | egress 정책 — 어댑터 준비, 발급키 필요 |
| KCI / AI Hub | 차단 | egress 정책 |

확보 기관: 서울대병원·분당서울대·보라매·서울아산·삼성서울·세브란스·강남세브란스·
연세대·고려대·충남대(병원)·지엔티파마·말기신부전임상연구센터

> 기관 필터(`KR_INSTITUTIONS`)로 해외 기관을 배제한다 — ClinicalTrials 의 sponsor 검색은
> 퍼지 매칭이라 University of Houston 등이 섞여 들어온다.

## 데이터 성격 (정직한 기술)

한국어 문장은 **실제 국내 연구과제 메타데이터를 R&D 문체로 렌더링**한 것이다.
- **사실은 실데이터**: 기관명·과제번호·등록례수·개시연도 모두 실제 값
- **문장 형태는 템플릿**: 자연 한국어 코퍼스를 수집한 것이 **아니다**

따라서 한국어 토크나이제이션·수치/귀속 검증 평가에는 유효하지만,
**자연 한국어 문체 다양성 평가로는 부족하다.** 후자는 ScienceON/KCI 수집이 필요하다.

## ALCOA+ 속성별 변조 설계

환각 3유형이 아니라 **ALCOA+ 속성 위반**에 직접 대응시켰다.
국내 R&D 감사(연구노트 점검·GLP)에서 실제로 지적되는 항목이기 때문이다.

| 변조 | 위반 속성 | 현실 시나리오 |
|---|---|---|
| `sponsor_swap` | Attributable (귀속가능) | 타 기관 성과를 자기 성과로 귀속 |
| `enrollment_tamper` | Accurate (정확) | 등록례수 부풀리기 |
| `date_shift` | Contemporaneous (동시적) | 수행시점 소급 기재 |
| `id_fabrication` | Original (원본) | 존재하지 않는 과제번호 |
| `no_source` | Attributable | 출처 없는 주장 |

## 이 작업이 드러낸 실제 결함

한국어 데이터를 넣자마자 **국내 시장 대응이 불가능한 결함들**이 드러났다.

1. **한국어 인용을 전혀 인식하지 못함** — `extract_citations` 가 `[]` 반환.
   DOI/URL/영문 저자-연도만 지원했고, 국내 표기 `(출처: 기관, 연도, 과제번호 NCT...)` 는 미지원.
   → 과제번호(NCT/NRF/NTIS)·출처 블록·한국어 저자인용(`김철수 외 (2023)`) 패턴 추가.
2. **한국어 수치 단위 미인식** — `명·건·회` 가 단위 목록에 없어 **등록례수 변조를 못 잡았다**
   (ALCOA+ `Accurate` 검증 실패). 천단위 콤마(`2,927명`)도 미지원.
   → 한국어 단위 + 콤마 표기 추가.
3. **문단 끝 인용이 앞 문장을 귀속하지 못함** — 한국어 R&D 문체는 여러 문장 뒤에 출처를
   한 번 붙인다. 기존 로직은 인용이 붙은 문장만 커버로 계산해 `source_exist=0.25`.
   → 직전 인용 이후 문장들을 현재 인용이 흡수하도록 수정(영어에도 적용되는 의미 개선).
4. **인용 조각이 주장으로 잘못 전달됨** — 문장 분리 후 `"(출처: ...)"` 자체가 NLI 입력이 되어
   `source_match=0.0`. → 인용 앞 본문을 주장으로 사용하도록 수정.

## 결과

python -m compliance_gateway.data.korean.build_kr   # 데이터 생성

|---|---|---|---|---|
| 0.86 | 100% | 99.1% | 99.5% | 100% |
| **0.94** | **100%** | **100%** | **100%** | **100%** |

### ⚠️ 이 100% 를 KPI 근거로 쓰지 말 것

규칙 기반 변조 합성셋이다. **우리가 만든 오류를 우리가 찾는** 구조라 낙관적이다.
bioRxiv 합성셋(F1 98.2%)과 같은 성격이며, 외부 실데이터(SciFact F1 24.0%)와
**직접 비교할 수 없다.**

| 평가셋 | 성격 | 용도 |
|---|---|---|
| 합성 KR (본 데이터셋) | 템플릿+규칙변조 | 한국어 처리 회귀 테스트 |
| 합성 EN (bioRxiv) | 실논문+규칙변조 | 서지 검증 회귀 테스트 |
| 외부 EN (SciFact) | 전문가 주석 실데이터 | **KPI 근거** |
| **외부 KR** | **미확보** | ScienceON/KCI 필요 |

## 부수 발견: 언어별 운영점이 다르다

영어 외부셋 최적 θ=0.70, 한국어 합성셋 최적 θ=0.94.
한국어 템플릿은 근거-주장 어휘 중복이 커 VCR 이 전반적으로 높다.
→ 단일 임계값으로 다국어를 처리할 수 없다. 사업계획서의
**VCR v2 도메인별 가중치 자동 최적화**가 필요한 실증 근거.

# 실데이터 평가셋 (kr_protocols) — 성능 주장의 진짜 근거

위의 템플릿 합성셋은 회귀 테스트용이다. **한국어 성능을 주장하려면 실데이터가 필요**하므로,
국내 연구기관의 **실제 프로토콜 원문**으로 별도 평가셋을 구축했다.

## 구성 원리: 변조 없음, 라벨은 출처(provenance)에서 도출

우리가 문장을 만들거나 값을 변조하지 않는다. **다른 실제 과제의 원문을 잘못 귀속**시키면
그것이 곧 오류다. 라벨은 "이 값이 실제로 이 과제의 것인가"로 결정된다.

| 항목 | 양성 | 음성(실제 오귀속) | ALCOA+ |
|---|---|---|---|
| primary_outcome | 해당 과제의 실제 주요결과변수 | **다른 과제의 실제 결과변수** | Accurate |
| enrollment | 해당 과제의 실제 등록례수 | **다른 과제의 실제 등록례수** | Accurate |
| eligibility | 해당 과제의 실제 선정기준 | **다른 과제의 실제 선정기준** | Complete |
| institution | 실제 수행기관 | **다른 과제의 실제 수행기관** | Attributable |

음성이 **같은 도메인 국내 연구과제의 진짜 문장**이라 규칙으로 만든 티가 나지 않는다.
패턴 매칭이 아니라 실제 의미 근거 확인이 필요하다. SciFact 외부 평가와 같은 방식.

데이터: **국내 8개 기관 24개 과제**, 실제 서술 텍스트 **20,742자**.
→ 평가 **186건**(균형 93/93), DPO **93쌍**.

기관: 강남세브란스병원 · 국립암센터 · 삼성서울병원 · 서울대학교병원 · 서울아산병원 ·
지엔티파마 · 충남대학교병원 · 한국원자력의학원 원자력병원

확장 방법: `Clinical_Trials` MCP 의 `search_by_sponsor` 로 국내 기관 과제번호를 수집하고
`get_trial_details` 로 실제 프로토콜 원문을 받아 `scripts/build_kr_seed.py` 형식으로 고정한다.
같은 방법으로 수백 건까지 확장 가능하다(외부망에서는 직접 API 호출도 가능).

```bash
python -m compliance_gateway.data.korean.real_eval    # 생성
python -m compliance_gateway.eval.korean --real --threshold 0.64
```

## 결과 — 템플릿 성능은 거의 전부 인공물이었다

| 데이터셋 | n | AUC | 정상 평균 | 위반 평균 | 분리도 |
|---|---|---|---|---|---|
| 합성 KR(템플릿) | 132 | **1.000** | 0.9460 | 0.7249 | +0.2211 |
| 실데이터 KR (초기 9과제) | 70 | 0.715 | 0.6347 | 0.6166 | +0.0181 |
| **실데이터 KR (24과제)** | **186** | **0.704** | 0.6278 | 0.6109 | **+0.0169** |

> 데이터를 2.7배 늘려도 AUC 가 0.715 → 0.704 로 유지된다.
> **표본이 적어서 낮았던 게 아니라 모델 능력의 한계**임이 확인됐다.

**실데이터에는 사용 가능한 운영점이 없다.**

| θ | Precision | Recall | F1 | PASS |
|---|---|---|---|---|
| 0.60 | 62.5% | 5.4% | 9.9% | 96.8% |
| 0.64 | 69.9% | 54.8% | 61.4% | 76.3% (사용불가) |
| 0.68 | 53.8% | 100% | 69.9% | 14.0% (사용불가) |
| 0.72 | 50.5% | 100% | 67.1% | 2.2% (사용불가) |

- 위반 35건 **전부**가 정상 응답 최저점(0.606) 위에 있다 → **분포가 완전히 겹친다**
- 정상통과 80% 이상을 유지하는 임계값에서는 F1 = **0%**
- AUC 0.715 → 신호는 있으나(무작위 0.5보다 높음) 마진이 0.018로 너무 작다

### ALCOA+ 속성별 (θ=0.64)

| 속성 | 탐지율 | 해석 |
|---|---|---|
| Attributable (귀속가능) | **100%** | 기관 오귀속은 잘 잡는다 |
| Complete (완전) | 55.6% | 선정기준 오귀속은 절반 |
| **Accurate (정확)** | **29.4%** | **수치·결과변수 오귀속이 최대 약점** |

## 시사점

1. **템플릿 합성셋의 100% 는 KPI 근거가 될 수 없다.** 같은 게이트웨이가 실데이터에서는
   사용 가능한 운영점조차 갖지 못한다. 두 수치를 나란히 놓는 것 자체가 오해를 부른다.
2. **약점이 구체적으로 특정됐다** — `Accurate`(수치·결과변수 오귀속) 29.4%.
   국내 R&D 감사에서 가장 흔한 지적 유형이라 우선 개선 대상이다.
3. **트랜스포머 NLI 의 필요성이 한국어에서도 확인됐다.** 영어 외부셋(F1 24.0%)과 마찬가지로
   통계 NLI 로는 의미 근거 판정이 불가능하다.
4. 이 데이터셋은 **A100 NLI 파인튜닝 후 재측정의 한국어 기준선**이다(AUC 0.715 → 얼마).

## 한계

- 텍스트는 **영어**다. 국내 기관이 국제 등록부에 영어로 작성한 실제 R&D 문서이며,
  주장 전달 문구만 한국어 템플릿이다. **자연 한국어 R&D 문서(연구노트·국문보고서)는 여전히 미확보** —
  ScienceON/KCI(egress 차단) 또는 GOONO 실데이터가 필요하다.
- 24개 과제 규모다. 같은 방법으로 수백 건까지 확장 가능하나, **데이터를 2.7배 늘려도
  AUC 가 개선되지 않았다** — 병목은 데이터 양이 아니라 NLI 모델 능력이다.
