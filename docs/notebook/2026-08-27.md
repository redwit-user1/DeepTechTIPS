## 1. 목적

- 로컬에 확보된 약 7.7GB OCR 텍스트 코퍼스를 분석해 활용 가능성을 판정한다.

## 2. 수행

- 단일 대용량 CSV이므로 **스트리밍 리더** 구현(`csv_source.py`). 전량 적재를 금지한다.
  - 내보내기에서 개행이 리터럴 `\n`으로 이스케이프돼 있어 복원 처리 추가.
  - OCR 본문 한 셀이 매우 커서 `csv.field_size_limit` 상향.
- 비식별화 모듈을 추출 경로에 **강제 선행**. 원본·추출물의 저장소 커밋을 차단(`.gitignore`).
- 내용 기준 분류기, 분야 분류기(국가과학기술표준분류 10개 대분류), GitHub 커밋의 연구 관련성 판별기 구현.

## 3. 정정 사항

### 정정 07 — 연구노트의 판정 기준 (최중요)

국가연구개발 연구노트 **지침 양식**(과제명·연구자 서명·점검자 칸)을 기준으로 "구조성 지수 0.07 → 연구노트가 아니다"라고 판정했다. **이 기준이 잘못되었다.**

- 연구노트의 본질은 담긴 **연구 내용**이다.
- 서명·양식 등 형식 요소는 부차적이며 애초에 이 코퍼스에 담기지 않는다.
- 업로드된 문서 자체가 곧 연구 기록이다.

> 연구 내용 비율 **0.1% → 32.1% → 46.5%**

**파급:** `integrity/` 양식 검사 모듈의 가치가 낮아지고, **내용 근거 검증(VCR)이 핵심**으로 승격된다.

### 정정 08 — 흩어진 신호 누락

판정 조건이 "한 종류 신호 3개 이상"을 요구해, `수치 2 + 실험용어 2 + 분석어 2`처럼 여러 종류에 분산되면 전부 탈락했다.

- 조각 버킷 검사 결과 **21.7%가 신호 3개 이상**이었다.
- 숫자 10개 이상 포함 64.4%, 길이 300자 이상 67.2%(중앙값 533자) — 짧아서 밀린 것이 아니다.
- 최강 신호 범주로 배정하도록 수정.

### 정정 09 — 도달 불가 분기

GitHub 설정·메타가 0건으로 나왔는데, 데이터가 없어서가 아니라 진입 조건 통과 시 하위 세 분기 중 하나가 반드시 참이 되어 해당 분기에 도달할 수 없었다.

> **0 → 7.1%**

### 정정 10 — 비식별화 1패스 부족

500건 검사에서 전화번호 4건이 잔존했다. 다중 패스(`MAX_PASSES=5`)로 전환.

> 치환 37 → 41건, 잔존 **0**

단, **구조는 보존**한다. "연구자: 홍길동"을 삭제하면 ALCOA+ *Attributable* 이 거짓으로 실패하기 때문에, "연구자: 연구자_A3F2" 형태로 치환한다.
