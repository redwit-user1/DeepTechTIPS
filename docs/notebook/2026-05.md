## 1. VCR 착상 — 사람 라벨 없는 보상 신호

### 1.1 설계 문제

- SLM을 규정준수 방향으로 정렬하려면 **선호 데이터(Preference)** 가 필요하다.
- 사람이 라벨링하면 규모를 낼 수 없다. 수만 건 단위가 필요한데 전문가 시간은 희소하다.
- → **객관적이고 자동 판정 가능한 기준**이 필요하다.

### 1.2 착상

> "출처가 존재하는가"는 사람의 판단 없이 기계가 판정할 수 있다.
> 이것을 보상 신호로 삼으면 Preference 데이터를 대규모 자동 구축할 수 있다.

### 1.3 정의

```
VCR(y|x) = w1·SourceExist(y) + w2·SourceMatch(y) + w3·ALCOA_Score(y) + w4·(1 − Halluc(y))
```

| 항 | 의미 | 1차 구현 | 목표 구현 |
|---|---|---|---|
| `SourceExist` | 인용 존재 여부 (DOI/URL/논문명 식별) | 정규식·식별자 파서 | 패턴 + 외부 DB 대조 |
| `SourceMatch` | 인용과 실제 내용의 일치도 | 휴리스틱(키워드 중첩) | **NLI entailment** |
| `ALCOA_Score` | 데이터 무결성 | 규칙기반 체크 | 온톨로지 추론 |
| `Halluc` | 환각 탐지 (낮을수록 좋음) | 휴리스틱 | NLI 기반 + DB 대조 |

- 가중치 합 = 1, 출력 범위 `[0,1]`
- DPO 기준선 **0.60**, 최종 목표 **0.85+**

### 1.4 보상 해킹 방지 설계

착상 단계에서 이미 예상되는 공격 경로와 대응을 정의했다.

| 공격 | 대응 |
|---|---|
| 형식적 출처를 다는 것만으로 점수 획득 | `w2·SourceMatch`가 `w1·SourceExist`를 견제 |
| 정렬 과정에서 성능 붕괴 | VCR이 기준선(0.60) 미만이면 **자동 롤백**(Graceful Degradation) |
| RLVR 전환 시 보상 폭주 | GRPO 질의당 N=8 샘플링 후 **상대 어드밴티지** 학습 |

### 1.5 DPO Preference 쌍 형식

```
y_w (선호)  : "Kim et al. (2024)에 따르면, pH 7.4에서 반응속도가 2.3배 향상"   ← 출처 O, 정확 O
y_l (비선호) : "pH 7.4에서 반응속도가 향상되는 것으로 알려져 있습니다"          ← 출처 X
```

## 2. Compliance Gateway 구조 설계

### 2.1 7단계 파이프라인

모든 AI 출력이 반드시 통과한다. **Model-Agnostic** — 자체 LoRA와 외부 API를 모두 대응한다.

```
01 사용자 질의
02 Pre-Gen 제약 주입      (개인정보·규정위반 가능성 사전 스크리닝)
03 SLM / API 생성
04 출처 바인딩            (문장 수준 인용 자동 태깅)
05 NLI 게이팅             (임계값 θ 미달 → 차단 / 자동 재생성 1~3회)
06 ALCOA+ 체크포인트
07 블록체인 감사추적      (생성시점·모델ID·출처·NLI점수·ALCOA점수 불변 기록)
```

### 2.2 설계 결정 — 두 경로 명시 분기

API 모델은 로짓 접근이 불가하므로 in-process 게이팅이 **물리적으로 불가능**하다.

| 모드 | 대상 | 개입 시점 | 정밀도 |
|---|---|---|---|
| `mode="logit"` | 자체 LoRA | 토큰 생성 중 | 최고 |
| `mode="post"` | API 모델(GPT/Claude) | 생성 완료 후 텍스트 기반 | 후퇴 |

- API 경로는 사용자에게 우선 노출 + "검증 중" 배지 → 백그라운드 NLI 완료 후 확정(Adapter 패턴).
- **판단: 이 갭을 제품·마케팅에서 정확히 커뮤니케이션하는 것이 신뢰성 확보의 전제다.**
  숨기면 "모든 출력을 실시간 검증한다"는 과장이 되고, 한 번 발각되면 제품 전체의 신뢰가 무너진다.

### 2.3 4대 축

| 축 | 내용 | 우선순위 |
|---|---|---|
| ① Compliance-Aligned SLM | 7B 베이스 + 도메인 LoRA, DPO → RLVR(GRPO) 정렬 | |
| ② **Compliance Gateway** | 7단계 파이프라인, Model-Agnostic | **1순위** |
| ③ R&D 에이전트 + DAG | 탐색·기획 / 실험분석·설계 / 규정준수·재현성 3종, LangGraph | |
| ④ Harnessing | Data Flywheel, R&D 특화 RAG, 프로젝트 메모리 L1/L2, 듀얼배포 | |

- 베이스 모델 후보: EXAONE 3.5 7.8B / Qwen 3.5 7B / Gemma — **모두 Apache 2.0**. 라이선스 제약을 사전에 제거했다.
- 에이전트는 **Human-in-the-loop 필수**. 규정준수 에이전트는 판단하지 않고 제안만 하며 연구자 승인을 받는다.

### 2.4 Compliance Data Flywheel

```
사용 → 검증기록 → Preference 데이터 → 분기별 재학습 → 품질향상
  ↑                                                      │
  └──────────────────────────────────────────────────────┘
```

- 구조적 해자(moat)의 근거. 쓸수록 검증 기록이 쌓이고, 그것이 곧 학습 데이터가 된다.

## 3. KPI 설계

사업계획서 기준 8개 지표를 확정했다.

| 지표 | 개발 전 | 목표 |
|---|---|---|
| R&D 보고서 자동생성 정확도 | 72% | 85 → **88%+** |
| 도메인 질의 정확도 | KISTI 2.5 | **2배+** |
| AI 생성 콘텐츠 출처 정확률 | 없음 | **90%+** |
| 에이전트 워크플로우 자동화율 | 없음 | **85%+** |
| 양자화 후 성능 보존율 (FP16 대비) | 없음 | **80%+** |
| 규정위반 탐지 정밀도 | 없음 (경쟁사 전무) | **90%+** |
| 규정 온톨로지 커버리지 | 없음 | **90%+** |
| 접근통제 정확도 (RBAC/ABAC) | 없음 | **99%+** |

## 4. 마일스톤 및 스코프 방어

### 4.1 원칙

**Gateway-First · Data-Driven · Demo-Early.**
사업계획서의 4년 계획을 그대로 옮기지 않고 **레버리지가 가장 큰 모듈부터 압축**한다.

| 단계 | 목표 | 검증 기준 |
|---|---|---|
| M0 | 레포 스캐폴딩 + VCR/Gateway 골격 | 단위테스트 통과 |
| M1 | Gateway v1 (API 모델 대상) | 가짜 DOI·수치변조 탐지 데모 |
| M2 | R&D Instruction 데이터 파이프라인 | 트리플 5만건, 전문가 교차검증 표본 |
| M3 | Compliance-Aligned SLM v1 | VCR 0.60+ 기준선 |
| M4 | R&D 에이전트 v1 + DAG | 선행연구→갭→제안서 단일 워크플로우 |
| M5 | In-process 게이팅 + Flywheel | VCR 자기진화 루프 |

### 4.2 의도적 후순위 — 스코프 방어

코어 3축이 **VCR 0.7+** 를 찍기 전까지 아래는 착수하지 않는다.

- 멀티모달(수식·차트·현미경 이미지)
- RLVR 완전 전환
- 일본 PMDA / 싱가포르 A*STAR 모듈
- 풀 온톨로지 자동추론

> 명시적 스코프 방어선을 문서에 남겨 두는 것이 목적이다. 진행 중 확장 압력이 들어올 때 판단 근거가 된다.
