# 연구노트 2026-09-02

| | |
|---|---|
| **단계** | 분류기 검증 |
| **주제** | 분류기 일치도 측정, 전 구간 재판정, 혼동행렬 역산 보정 |
| **관련 커밋** | (본 커밋) |

## 1. 목적

두 가지 미해결 항목을 수행한다.

1. **분류기 정확도 검증** — 지금까지의 모든 분류 수치가 정확도 미검증 상태다.
2. **버킷·분야 전 구간 재판정** — 기존 수치가 앞부분 연속 60,000행 표본이라 구간 편향 가능성이 있다.

## 2. 수행 ① 분류기 일치도

### 2.1 방법과 그 한계

정규식 분류기와 **독립적인 2차 판정**을 180건 수행했다.
**사람 검수가 아니므로 "정확도"가 아니라 "일치도"다.**
`label`(사람 몫) 칸은 비워 두고 `model_label` 칸에 기록했다.

### 2.2 결과

| 판정 단위 | 표본 일치도 | 코퍼스 가중 |
|---|---|---|
| 10개 버킷 | 48.9% | **43.1%** |
| 3대분류(연구/GitHub/기타) | 76.1% | **69.5%** |

| 대분류 | 재현율 | 정밀도 |
|---|---|---|
| 연구내용 | 78.7% | 87.6% |
| GitHub | 78.8% | 95.3% |
| 기타(조각·행정) | 55.0% | **27.5%** |

`fragment` 단독 정밀도는 **9.4%** — 조각이라 판정한 것 중 실제 조각은 10건 중 1건이다.

주요 혼동 (180건 중):

```
연구내용 → 기타            22건   ← 한 방향으로 쏠림
기타   → 연구내용           8건
code_commit → code_meta   9건
experimental ↔ analysis  12건
```

### 2.3 판정

- **세부 버킷(10종) 수치는 철회한다.** 43.1%는 사용 불가.
- **대분류는 방향만 유효하다.** 오분류가 연구→기타 한 방향으로 쏠려 있고
  정밀도(87.6%)가 재현율(78.7%)보다 높으므로, **연구 내용은 46.5%보다 많다.**
- GitHub 정밀도 95.3%는 양호하다. 다만 하위 4종 구분은 무의미하다.

## 3. 수행 ② 전 구간 재판정

앞부분 편향을 없애기 위해 파일 전체를 순회하며 20행마다 판정했다(282,717행).

| | 앞부분 60,000행 | **전 구간 282,717행** | 괴리 |
|---|---|---|---|
| 연구 내용 | 46.54% | 46.48% | 0.06p |
| GitHub | 14.59% | 14.49% | 0.10p |
| fragment | 38.36% | 38.53% | 0.17p |
| 생명·보건의료 | 22.67% | 22.84% | 0.17p |

**최대 괴리 0.2p.** 앞부분 표본은 전 구간을 잘 대표했다.

### 판정

**구간 편향은 없었다. 문제는 표본 위치가 아니라 분류기였다.**
이 결과로 "앞부분 6만 행이라 못 믿는다"는 그동안의 유보를 해제한다.

## 4. 혼동행렬 역산 보정

두 측정이 서로 다른 것을 알려주므로 합칠 수 있다.

- 전 구간 판정 → 분류기의 예측 분포 `P(pred)` (구간 편향 없음이 확인됨)
- 라벨셋 → 예측 버킷별 실제 분포 `P(gold | pred)` (예측 버킷 기준 층화 추출이므로 편향 없음)

```
P(gold=g) = Σ_p  P(gold=g | pred=p) · P(pred=p)
```

분류기가 **일관되게** 틀리면 그 틀림 자체를 보정할 수 있다. 계통 오차이지 노이즈가 아니기 때문이다.

### 결과 (3대분류)

| | 관측 | 보정 | 변화 |
|---|---|---|---|
| 연구 내용 | 46.48% | **65.58%** (±7.65) | +19.1p |
| GitHub | 14.49% | **23.48%** (±6.15) | +9.0p |
| 기타 | 39.03% | **10.94%** (±6.09) | −28.1p |

## 5. 이 보정을 어디까지 믿을 것인가

### 레버리지 문제 — 10개 버킷 보정은 쓸 수 없다

층화 추출이 버킷마다 비슷한 수를 뽑았는데, **코퍼스 질량은 전혀 균등하지 않다.**
그래서 판정 1건이 전체 비율을 움직이는 폭이 버킷마다 20배 차이 난다.

| 예측 버킷 | 코퍼스 질량 | 판정 표본 | 1건당 영향 |
|---|---|---|---|
| fragment | 38.53% | 32건 | **1.20p** |
| experimental | 33.17% | 30건 | **1.11p** |
| code_meta | 7.08% | 10건 | 0.71p |
| analysis | 9.66% | 27건 | 0.36p |
| literature | 2.13% | 23건 | 0.09p |
| admin | 0.50% | 8건 | 0.06p |

**상위 2개 버킷이 코퍼스의 71.7%를 차지하는데 판정은 62건뿐이다.**

`planning 1.52% → 16.05%` 같은 값은 fragment 표본 32건 중 7건이 계획으로
판정된 결과이며, 7건이 8.4 퍼센트포인트를 움직였다. **너무 취약해 쓸 수 없다.**

### 표본 설계의 오류

| 목적 | 필요한 표본 설계 |
|---|---|
| 버킷별 정확도 측정 | 버킷 **균등** 층화 ← 현재 설계 |
| 전체 비율 보정 | 예측 **질량 비례** |

두 목적이 서로 다른 설계를 요구하는데 하나만 만들었다.

## 6. 정정 사항

### 정정 16 — 세부 버킷 비율 철회

실험 33.2% / 분석 9.6% / 문헌 2.2% / 계획 1.5%, 그리고 분야 분포(생명 22.7% 외)를
**철회한다.** 10개 버킷 일치도가 43.1%이고, 분야 분류는 그 위에 얹힌 값이다.

### 정정 17 — 구간 편향 유보 해제

"앞부분 연속 6만 행이라 대표성이 없을 수 있다"는 유보를 **해제한다.**
전 구간 재판정 결과 최대 괴리 0.2p로, 표본 위치는 문제가 아니었다.

### 정정 18 — CSV 배너 파싱 결함

`build_label_set.py`가 쓴 배너를 `#` 시작 줄 필터로 걷어냈는데,
인용 필드 **안**의 본문 줄이 `#`로 시작하면 그것까지 지워져 CSV가 깨졌다.
헤더 앞부분만 걷어내도록 수정.

## 8. 차기 계획

1. **fragment·experimental 버킷에 라벨 집중** — 각 200건 이상.
   두 버킷이 코퍼스의 71.7%를 쥐고 있다. 균등 층화가 아니라 질량 비례로 뽑는다.
2. **사람 검수** — 현재 판정은 모델 2차 판정이다. 보정값은 그것을 정답으로 가정한 결과다.
3. **분류기 수정** — `fragment` 정밀도 9.4%가 최대 결함. 조각 판정을 대폭 좁혀야 한다.
4. 근거·주장 쌍 생성은 3번 이후로 미룬다.

## 9. 한 줄

**비율은 안정적인데 라벨이 틀렸다.** 분류기가 일관되게 틀리므로 보정은 가능하지만,
질량이 큰 두 버킷의 표본이 62건뿐이라 보정값 자체가 아직 불안정하다.
