# 실제 GOONO OCR 코퍼스 분석 결과

> 로컬 보유 `ocr_goono_ocr_texts.csv` (**7.7GB**) 를 직접 분석한 기록.
> 원문·파일명은 이 문서에 포함하지 않는다. 통계와 구조만 남긴다.

## 데이터 형식 — 예상과 달랐다

| 예상했던 것 | 실제 |
|---|---|
| `.txt` 파일 디렉터리 | **단일 CSV** `id, NoteId, fileName, page, text` |
| 파일 1개 = 노트 1건 | NoteId 당 여러 page (표본 평균 1.1페이지) |
| 실제 개행 | 리터럴 `\n` 이스케이프 |
| 연구노트 본문 | **업로드된 각종 연구자료** |

→ `data/ocr/csv_source.py` 로 스트리밍 리더를 새로 만들었다(전체 적재 불가).

## 규모

- 파일 7.7GB, 표본 평균 행 1.2KB → **전체 약 652만 행** 추정
- 본문 길이 중앙값 770자 / 평균 978자 / 최대 20,742자
- 빈 본문 0%

## 핵심 발견 ① — 연구노트가 아니다

**구조성 지수 0.07** (우리 가상 연구노트는 1.00).

원본 파일 확장자 분포:

| 확장자 | 비율 |
|---|---|
| `.pdf` | 63.9% |
| `.pptx` | 12.5% |
| `.xlsx` | 8.6% |
| `.docx` | 7.1% |
| 이미지(jpg/png) | 2.5% |
| `.hwp` | 0.8% |

즉 **연구노트 양식 문서가 아니라, 연구자들이 GOONO 에 업로드한 첨부 연구자료**다.
논문 PDF·발표자료·데이터 표가 대부분이다.

→ `integrity/` 연구노트 무결성 검사기를 **코퍼스 전체에 적용할 수 없다.**

## 핵심 발견 ② — 용도별로 나눠야 한다

`scripts/triage_ocr_csv.py` 로 10만 행을 판정한 결과:

| 버킷 | 표본 비율 | 전체 추정 | 쓰임 |
|---|---|---|---|
| 연구노트형 | 0.1% | 약 4,000행 | 기록 무결성 검사 — **표본이 너무 적다** |
| **인용 포함** | 0.5% | 약 **33,600행** | **한국어 VCR 출처 검증** ← 최대 공백이던 항목 |
| **한국어 서술** | 23.5% | 약 **153만행** | **SLM 도메인 적응·RAG** ← 최대 가치 |
| 표/수치형 | 20.1% | 약 131만행 | 구조·수치 검증 |
| 저가치(200자 미만·잡음) | 55.8% | 약 364만행 | 제외 |

버킷별 평균 본문 길이: 인용 포함 **3,003자**(가장 김 — 논문 본문), 표 1,001자,
연구노트형 925자, 한국어 서술 859자.

### 시사점

1. **한국어 KPI 의 길이 열렸다.** 지금까지 한국어 평가는 전부 합성이었고
   "외부 한국어 평가셋 미확보"가 최대 공백이었다. `cited` 버킷 3.4만 행이
   **실제 한국어 문서 + 실제 인용**이라 VCR 평가에 쓸 수 있다.
2. **SLM 학습 데이터 규모 문제가 해소된다.** 사업계획서 목표는 R&D Instruction
   5만 건인데, `korean_prose` 153만 행이면 충분하고도 남는다.
3. **연구노트 무결성 검사의 실데이터 검증은 여전히 미해결.** 4,000행은
   사람 검수 표본으로는 쓸 수 있으나 통계적 성능 측정에는 부족하다.

### 주민등록번호는 대부분 오탐이었다

`scripts/check_rrn_risk.py` 로 **값을 보지 않고 체크섬만** 검증했다
(실제 주민번호는 마지막 자리가 검증번호).

| 지표 | 결과 | 무작위 기대치 |
|---|---|---|
| 체크섬 통과 | 10.6% | 약 9% (1/11) |
| 생년월일 형식 | 20.4% | — |
| 둘 다 통과 | **4.3%** | — |

→ 대부분 과제번호·날짜 조합의 오탐. 다만 4.3%는 배제할 수 없으므로
비식별화 규칙은 유지한다.

## 실데이터가 잡아낸 비식별화 버그 — 1회 패스로는 부족했다

추출 시 비식별화 **이후에도 11자리 전화번호가 잔존**했다(500건 중 4건).
2차 패스를 돌리자 잡혔다 — 인접·중첩 매치를 정규식 1회 스캔이 놓친 것이다.

> 개인정보가 남으면 안 되므로 `deidentify()` 를 **잔존이 0 이 될 때까지 반복**
> (최대 5패스) 하도록 수정했다. 재추출 결과 전화번호 37 → 41건으로 4건 더 잡혔고
> **잔존 위험 0** 을 확인했다.

진단은 `scripts/debug_residual_pii.py` 로 **값을 노출하지 않고 형태만**(D=숫자,
K=한글, A=영문) 확인했다.
