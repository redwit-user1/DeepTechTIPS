# 외부 실데이터 평가 — 정직한 KPI 기준선

> **핵심 결론: 합성 평가셋 F1 98.2% vs 외부 실데이터 F1 39.3%.**
> 이 59%p 격차가 과제의 실제 상태다. 목표(90%+) 달성에는 트랜스포머 NLI 가 **필수 조건**이며,
> 임계값 보정으로는 도달 불가함을 실데이터로 확인했다.

## 왜 필요한가

합성 평가셋(bioRxiv 변조)은 **우리가 만든 오류를 우리가 찾는** 구조다.
변조 규칙을 아는 검증기가 잘 잡는 건 당연하므로 성능이 낙관적으로 나온다.
과제 성능지표(규정위반 탐지 90%+, 출처 정확률 90%+)를 *증명*하려면
제3자가 만든 실데이터가 필요하다.

## 데이터

**SciFact** (Wadden et al., EMNLP 2020) — 전문가 작성 과학 주장 + 실제 PubMed 근거,
SUPPORT/CONTRADICT 전문가 주석. **우리가 변조를 가하지 않는다.**

### 평가 시나리오: "인용은 실존하나 주장을 뒷받침하지 않음"
현실에서 가장 흔하고 위험한 실패 유형(가짜 DOI 보다 훨씬 흔하다).

| SciFact 라벨 | 구성 | 기대 동작 |
|---|---|---|
| SUPPORT | 주장 + 실제로 뒷받침하는 논문 인용 | Gateway PASS |
| CONTRADICT | 주장 + 실제로 **반박하는** 논문 인용 | Gateway 차단 |

인용된 논문은 코퍼스에 실존하므로 서지 검증은 통과한다.
→ 이 평가는 **순수하게 SourceMatch(근거-주장 일치) 능력**을 측정한다.

## 실행

```bash
bash scripts/download_scifact.sh
python -m compliance_gateway.eval.external --split train --sweep
```

## 결과 (train, n=957: compliant 616 / unsupported_claim 341)

### θ=0.55 (합성 기준 운영점)

| 지표 | 합성 평가셋 | **외부 실데이터** |
|---|---|---|
| 위반탐지 Precision | 98.2% | **41.0%** |
| 위반탐지 Recall | 98.2% | **37.8%** |
| 위반탐지 F1 | 98.2% | **39.3%** |
| compliant PASS | 90.9% | 69.8% |

### 임계값 스윕 — '보정 문제' vs '모델 한계' 분리

| θ | Precision | Recall | F1 | PASS |
|---|---|---|---|---|
| 0.50 | 29.5% | 6.7% | 11.0% | 91.1% |
| 0.55 | 41.0% | 37.8% | 39.3% | 69.8% |
| 0.60 | 37.8% | 78.0% | 51.0% | 29.1% |
| 0.70 | 35.7% | 99.4% | 52.5% | 0.8% |
| 0.75+ | 35.6% | 100% | 52.5% | 0.0% |

- **최고 F1(제약 없음) 52.5%** — θ=0.75, 그러나 PASS 0% = *전부 차단* 축퇴점.
  Recall 100% 는 다 막아서 얻은 값이고 Precision 은 위반 기저율(35.6%)에 수렴 → 무의미.
- **최고 F1(정상통과≥80%) 11.0%** — 실사용 가능한 최선.
- **어떤 임계값에서도 Precision 이 41% 를 못 넘는다.**

> → 임계값 보정 문제가 **아니다**. 모델 능력 문제다.
> 통계 NLI(SciFact AUC 0.57)로는 목표에 도달할 수 없으며,
> **트랜스포머 NLI 도입이 KPI 달성의 필수 조건**임이 실데이터로 확정됐다.

## 이 평가가 잡아낸 실제 버그

합성 데이터에서는 드러나지 않던 결함이 실데이터에서 즉시 노출됐다.

1. **결측 메타데이터 감점 버그** — 제목만 있는 인용(저자·연도 없음)이 무조건 환각 판정.
   합성 인용은 항상 DOI+저자+연도를 다 갖고 있어 노출되지 않았다.
   원인: 없는 필드를 0점 처리 → `0.60×1.0 = 0.60 < 0.70`(PARTIAL 임계) → HALLUCINATED.
   수정: **가용 필드로만 가중치 정규화**. (`verify/scoring.py`)
   효과: compliant PASS 0% → 69.8%
2. **제목 인용 미추출** — LLM 이 DOI 없이 제목만 인용하는 흔한 형태를 놓치고 있었다.
   수정: 큰따옴표 제목 인용 추출 추가. (`vcr/source_exist.py`)
3. **레지스트리 선형 스캔** — 대규모 레지스트리에서 평가가 수 분 소요.
   수정: 정규화 제목 정확 인덱스 O(1) 우선 조회.

## 공정 비교 프로토콜 (데이터 누출 방지)

NLI 는 SciFact **train** 으로 파인튜닝한다. 따라서 **KPI 는 반드시 `dev` 로 측정**해야 한다.
같은 split 으로 재측정하면 학습 데이터를 재평가하는 셈이라 수치가 부풀려진다.
→ `eval/external.py` 에 가드를 넣어 `--nli` + `--split train` 조합을 **차단**한다
(진단 목적이면 `--allow-leakage` 명시).

### dev 기준선 (학습 전, 통계 NLI v0.5) — 파인튜닝 후 비교 대상

| θ | Precision | Recall | F1 | PASS |
|---|---|---|---|---|
| 0.50 | 36.7% | 9.0% | 14.5% | 91.2% |
| **0.55** | **39.0%** | **39.3%** | **39.2%** | 65.3% |
| 0.60 | 35.4% | 73.8% | 47.9% | 24.1% |

train(39.3%)과 dev(39.2%)가 거의 동일 → **발견이 특정 split 우연이 아님**을 확인.

## M1 실행 (A100)

```bash
bash scripts/run_m1_a100.sh          # 준비→검증→기준선→파인튜닝→재측정 자동
```

개별 실행:
```bash
python -m compliance_gateway.train.nli_finetune --dry-run          # GPU 없이 검증
python -m compliance_gateway.train.nli_finetune --output checkpoints/nli
python -m compliance_gateway.eval.external --split dev --nli checkpoints/nli --sweep
```

## 시사점 (로드맵 반영)

| 항목 | 반영 |
|---|---|
| 트랜스포머 NLI | **선택 아닌 필수**. M1 최우선, A100 첫 작업으로 확정 (`scripts/run_m1_a100.sh`) |
| 합성 평가셋 | 회귀 테스트용으로 유지하되 **KPI 근거로는 사용 금지** |
| KPI 보고 | 모든 성능 주장은 외부 실데이터 기준으로 병기 |
| 목표 재점검 | 현재 39.3% → 90% 는 큰 격차. NLI 파인튜닝 후 재측정으로 실현 가능성 판단 |

## 한계 (정직한 기술)

- SciFact 는 **영어·바이오** 도메인이다. 한국어 R&D 문서 성능은 별도 평가셋이 필요하다.
- SciFact 코퍼스에는 저자·연도·DOI 가 없어 **서지 검증 능력은 이 평가로 측정되지 않는다**
  (서지 변조 탐지는 합성 평가셋에서 측정: biblio_tamper 100%).
- FDA Warning Letters(실제 규정위반 텍스트)는 본 환경에서 네트워크 차단으로 미연동.
  → GLP/Part 11 조항 단위 위반 탐지 평가는 A100/외부망 환경에서 추가 필요.
